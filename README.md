# ドライブ発見アプリ (drive-discovery-app)

## コンセプト

このアプリは「行き先を決めるためのアプリ」ではありません。

**何気ない時間や移動を、新しい発見と思い出に変えるアプリ**です。

特に重視しているのは、旅行先で土地勘がないユーザーが、レンタカーの返却時刻や残り時間から、景色の良い道・穴場・寄り道を含むルートを見つけられる体験です。目的地ありきの効率的なナビではなく、「移動そのもの」を楽しくすることを目指します。

## 提供する価値

- 移動時間そのものを、発見と体験の時間に変える
- 「返却時刻まであと〇時間」といった制約の中で、無理なく楽しめる寄り道を提案する
- 土地勘がない場所でも、安心して寄り道を選べる
- 偶然の発見(セレンディピティ)を後押しする
- 移動の記憶を思い出として残せるようにする

詳しいプロダクト定義は [docs/PRODUCT.md](./docs/PRODUCT.md) を参照してください。

## 主な機能

現在実装済みなのは、以下の一連の流れ(縦断機能)です。

- **ホーム** — アプリのコンセプトと4つの入口(今からドライブ/旅行先で探す/みんなのドライブ/記録を見る)を表示。今回操作できるのは「今からドライブ」のみで、他は準備中の表示になります
- **出発地点を選ぶ** — 現在地(位置情報の許可・拒否どちらもハンドリング)、自宅(初回は地図で登録、以降はexpo-secure-storeに保存した座標を再利用。登録済みの自宅は「自宅を変更」で登録し直せます)、地図で指定した場所、の3通りから選べます。地図での確定時は、その瞬間のネイティブカメラ中心を検証して使用します
- **今日はどんなドライブにする?(条件入力ウィザード)** — 1画面フォームではなく、「今日の気分」→「どれくらい走る?」→「最後はどこにする?」→「経由したい場所はある?」→「何時ごろ戻る?」→「AIに追加で伝えたいこと」→「条件確認」の順に1ステップずつ進むウィザード形式です。画面上部に「2 / 7」のような軽い進捗表示があります(出発地点選択が1/7)
  - **今日の気分**: 景色重視/海沿い/山道/夜ドライブ/のんびり/寄り道多め/とにかく走りたい/おまかせ、から最大3つまで複数選択(「おまかせ」を選ぶと他の選択は解除され、他を選ぶと「おまかせ」は解除されます)
  - **どれくらい走る?**: 1時間/2時間/3時間/半日/1日/自分で入力/指定なし。「自分で入力」は日・時間・分を数字で入力でき(例: 2日12時間30分)、合計15分未満の場合は「15分未満では十分なルートを提案できない場合があります。15分以上に設定してください。」と表示され、次のステップへ進めません。「指定なし」は時間を決めず、ルート生成側で標準的な長さを仮に使います(将来AIが適切な時間を提案できる構造にしています)
  - **最後はどこにする?**: 出発地点に戻る/別の場所。「別の場所」は地図で目的地を指定できます(将来、検索・保存済み場所からの選択にも拡張しやすい構造にしています)
  - **経由したい場所はある?**: AIへの提案候補ではなく、ユーザーが実際に立ち寄りたい優先度の高い場所を複数追加できます。地図から選ぶ/保存済み場所から選ぶ/最近使った場所から選ぶ、の3通りで追加でき、地図で選んだ場所は任意で名前を付けて「保存済み場所」として端末内(expo-secure-store)に保存できます。直近使った場所は自動的に「最近使った場所」として記録されます
  - **何時ごろ戻る?**: 指定なし/日時を指定。日付(今日/明日/明後日/日付を指定)と時・分を組み合わせ、ISO 8601形式(例 `2026-09-03T02:00:00+09:00`)の帰着日時として保持するため、日付をまたぐ帰着(例: 翌日の深夜)も正しく扱えます
  - **AIに追加で伝えたいこと**: 自由記述欄。キーボード表示時も入力欄・ボタンが隠れないようにしています
  - **条件確認**: すべての選択内容を一覧表示し、各項目の「変更」から該当ステップへ戻って編集できます(入力済みの内容は保持されたままです)。「今日のルートを見つける」を押すと、すぐにルート比較へは進まず「あなたに合うドライブを考えています」という短い演出(モック待機。将来AI API接続に差し替え予定)を挟んでからルート提案に進みます
  - ルート比較画面には「条件を変える」ボタンがあり、押すと条件確認ステップから編集を再開できます(入力済みの条件は消えません)
  - 寄り道の量は「今日の気分」の選択(寄り道多め)から自動的に決まり、使える時間と帰着日時の短い方を時間予算としてルート提案処理に渡す既存の仕組みをそのまま再利用しています
- **3つのルートを提案する / 地図上でルートを比較する** — 選んだ「今日の気分」に応じて内容が変わる「景色重視ルート」「バランスルート」「のんびりルート(または短時間ルート)」の3ルートを提案します。各カードにはルート名・距離・所要時間・特徴・どんな人向けかを表示し、地図上のPolylineとカードの横スワイプで見比べられます。画面上部には「今日の気分: 景色重視・海沿い・2時間くらい」のように、選んだ条件が一目で分かる表示があります
- **周辺スポットを探す(寄り道探し)** — ルート決定確認画面から「周辺スポットを探す」を選ぶと、寄り道スポット探索画面(`app/spot-discovery.tsx`)へ進みます。画面上部の「おすすめ/ごはん/カフェ/絶景/温泉/アクティビティ」のカテゴリチップを切り替えると、地図上のマーカーとスポットカードが同じ条件で絞り込まれます(「おすすめ」は全カテゴリから表示)。カードを選ぶと対応するマーカーが、マーカーを選ぶと対応するカードが選択状態になります。気になる場所は「ここ寄ってみる」で最大3件まで選べ、時間予算を超える場合は選べません(「行くのをやめる」で外せます)。スポットは常に任意で、1件も選ばずに進むこともできます
- **ルートを決定する** — 「このルートにする」を押すと、選択したルート名・距離・所要時間・特徴を表示するルート決定確認画面(`app/route-summary.tsx`)へ進みます(戻る操作でルート比較画面へ戻れます)。スポットを選んだ場合は「この内容で決定」の完了画面から、選ばなかった場合は「このルートでナビ」の完了画面から、それぞれ「ドライブを開始」でドライブ記録画面へ進めます
- **ドライブを記録する** — ドライブ記録画面(`app/drive-recording.tsx`)で「記録を開始」を押すと、経過時間・走行距離・現在地・記録状態(記録前/記録中/記録終了)を表示しながら記録します。実GPS(expo-location)が使える場合は一定間隔(5秒ごと)で位置を記録し、Expo Go・権限拒否・シミュレーター等で実GPSが使えない場合は選択中ルートの経路に沿って自動的に往復するデモ走行モードへフォールバックします。「ドライブを終了」を押すと記録結果確認画面(`app/drive-summary.tsx`)へ進み、走行時間・走行距離・記録した座標数・選択したルート・経由したスポットを確認できます
- **日記を作成する** — 記録結果確認画面の「日記を作成」から日記作成画面(`app/drive-diary-create.tsx`)へ進み、タイトル・ひとことメモ・日付を入力できます(走行距離・走行時間・選択したルート・経由したスポットは記録結果から表示、編集はしません)。端末の写真ライブラリから写真を最大3枚選べます(expo-image-picker。許可拒否やExpo Go等で使えない場合も、写真なしで日記作成を続けられます)。「日記を保存」を押すと日記確認画面(`app/drive-diary-confirm.tsx`)へ進み、保存した内容を確認できます
- **日記を共有する** — 日記確認画面の「共有する」から共有画面(`app/drive-diary-share.tsx`)へ進み、PHOTO(写真背景+GPSルート線)/DATA(数字カード)/MEMORY(写真+メモ)の3種類のテンプレートを切り替えてプレビューできます。「共有する」を押すとプレビューを画像化し、OS標準の共有シート(Instagram/LINE/AirDrop/保存など、端末にインストールされたアプリに応じて選択肢が変わります)を開きます。GPSルート線は正規化した相対座標だけから描画するグラフィックで、地図タイルやマップアプリのスクリーンショットは使いません

> 位置情報・ルート検索は現時点ではすべてモックデータと端末機能(expo-location / expo-secure-store)で実装しており、Google Routes API・Google Places API・Supabase等の外部有料サービスとはまだ接続していません。ドライブ記録・日記もこの段階ではアプリ内状態(React Context)のみに保持し、端末・クラウドへの永続保存はまだ行っていません。共有もInstagram等の専用APIには接続せず、OS標準の共有機能のみを使っています。

今後実装を予定している機能は以下の通りです。

- 実際の道路データに基づくルート検索(Google Routes API等への差し替え)
- 住所からのスポット検索(Geocoding API等への差し替え)
- Instagram専用SDK/Meta連携、「みんなのドライブ」への投稿機能
- 記録・日記のローカル永続保存(アプリ再起動後も残す)とクラウド同期、旅行先モード

## 技術構成

- [Expo](https://expo.dev) (SDK 54)
- React Native / TypeScript
- [expo-router](https://docs.expo.dev/router/introduction/) によるファイルベースルーティング(スタックナビゲーション)
- `react-native-maps` … 地図表示・ルートのPolyline表示・場所指定のため追加(iOS/Androidのみ対応。Web版では未対応のためプレースホルダー表示になります)
- `expo-location` … 現在地の取得のため追加(許可ダイアログの表示、許可/拒否のハンドリング)
- `expo-secure-store` … 自宅座標を端末内に安全に保存するため追加(住所文字列ではなく緯度・経度を保存)
- `expo-image-picker` … 日記作成時に端末の写真ライブラリから写真を選ぶため追加(許可ダイアログの表示、許可拒否・Expo Go等で使えない場合のハンドリング)
- `react-native-view-shot` … 共有カード(PHOTO/DATA/MEMORY)のプレビューを画像ファイルとして生成するため追加
- `expo-sharing` … 生成した画像をOS標準の共有シート(Instagram/LINE/AirDrop/保存など)へ渡すため追加
- 現時点では有料の外部API(Google Routes, Google Places, Supabase, AI API等)は未使用です。UIとルート取得ロジックの間には `RouteProvider` / `GeocodingProvider` という差し替え可能な層を設けており、モック実装(`MockRouteProvider`)から将来のAPI連携実装へ差し替えられる構造にしています

技術方針の詳細は [docs/ARCHITECTURE.md](./docs/ARCHITECTURE.md) を参照してください。

## 起動方法

```bash
# 依存関係のインストール
npm install

# 開発サーバーの起動
npx expo start
```

起動後、ターミナルの案内に従って以下のいずれかで開けます。

- [Development build](https://docs.expo.dev/develop/development-builds/introduction/)
- Android エミュレータ
- iOS シミュレータ
- [Expo Go](https://expo.dev/go)

### iOS Expo Goでの確認手順

1. `npx expo start` を実行する
2. 表示されたQRコードを、スマートフォンにインストールした [Expo Go](https://expo.dev/go) アプリで読み取る
3. ホーム画面から「今からドライブ」→ 出発地点を選ぶ → ドライブ条件を入力する → ルートを比較する → ルート決定確認画面、まで一通り操作できることを確認する
4. 現在地を選ぶ際に表示される位置情報の許可ダイアログで「許可」「拒否」の両方を試し、拒否してもエラー画面にならず、再試行や他の出発地点の選択に進めることを確認する
5. **(iOS実機・確認済み)** ルート比較画面でルートを切り替えてもクラッシュせず、各ルートを選択できることを確認する
6. (確認済み)出発地点を「現在地」で選んで条件入力画面まで進んだあと、戻るボタンで出発地点選択画面に戻り、読み込み表示が固まらず操作できることを確認する
7. **(iOS実機・確認済み)** 出発地点選択画面で、自宅登録済みの状態から「自宅を変更」を押し、地図を動かして登録する。地図操作でクラッシュせず、変更後の自宅が保存されることを確認する
8. **(iOS実機・確認済み)** 「指定した場所」を押し、地図を動かして確定できることを確認する
9. **(iOS実機・確認済み)** ルート比較画面で「このルートにする」を押すと、ルート決定確認画面へ進めることを確認する
10. **(再確認項目)** ルート決定確認画面で「ルート比較に戻る」(または画面の戻る操作)を押すと、正しくルート比較画面に戻れることを確認する
11. **(再確認項目)** 出発地点を「指定した場所」で選んだ場合に、ルート決定確認画面まで進んでも出発地点選択画面の地図ピッカーが勝手に再表示されないことを確認する
12. **(再確認項目)** 1時間・寄り道多めで提案された全ルートが60分以内であることを確認する。過去の帰着時刻、または帰着まで10分未満になる時刻を選ぶと、条件変更を促す日本語メッセージが表示されることを確認する
13. **(再確認項目)** 現在地取得中にヘッダーまたは端末の戻る操作で画面を離れ、取得完了後に条件入力画面や出発地点選択画面が勝手に開かないことを確認する
14. **(iOS再確認項目)** 地図中心取得中・自宅保存中にiOS戻るジェスチャーまたはヘッダー戻るを行っても画面を離れず、処理完了後は通常どおり遷移または戻る操作ができることを確認する
15. **(iOS再確認項目)** 日付変更線をまたぐルートが、世界全体ではなく最小の経度範囲で表示されることを確認する
16. **(新規・要確認)** ルート決定確認画面の完了画面(スポットあり・なしどちらも)で「ドライブを開始」を押すと、ドライブ記録画面へ進めることを確認する
17. **(新規・要確認)** ドライブ記録画面で「記録を開始」を押し、位置情報の許可ダイアログで「許可」を選んだ場合、経過時間・走行距離・現在地(緯度経度)が更新され、記録状態が「記録中」になることを確認する
18. **(新規・要確認)** 位置情報の許可ダイアログで「許可しない」を選んだ場合、または機内モード等でGPSが取得できない場合でも、「デモ走行モード」の案内が表示され、選択中ルートに沿って現在地・走行距離が自動的に更新され続けることを確認する
19. **(新規・要確認)** 「ドライブを終了」を押すと記録結果確認画面へ進み、走行時間・走行距離・記録した座標数・選択したルート・経由したスポット(追加していれば)が表示されることを確認する
20. **(iOS実機・確認済み)** 記録結果確認画面で「日記を作成」を押すと日記作成画面へ進むことを確認する
21. **(iOS実機・確認済み)** 日記作成画面でタイトル・メモ・日付を入力でき、「写真を選ぶ」から写真ライブラリで最大3枚選択できることを確認する
22. **(iOS実機・確認済み)** 写真を選ばない(またはアクセスを許可しない)場合でも、写真なしのまま「日記を保存」に進めることを確認する
23. **(新規・要確認)** タイトル未入力、または日付をYYYY-MM-DD以外の形式にした状態で「日記を保存」を押すと、エラーメッセージが表示され保存されないことを確認する
24. **(iOS実機・確認済み)** 「日記を保存」を押すと日記確認画面へ進み、走行距離・走行時間・選択したルート・経由したスポット・写真が表示されることを確認する
25. **(iOS実機・確認済み)** 日記確認画面で「共有する」を押すと共有画面へ進み、PHOTO/DATA/MEMORYのタブでプレビューが切り替わることを確認する
26. **(iOS実機・確認済み)** 各テンプレートのプレビューに、緯度経度・住所などの正確な位置情報が文字として表示されていないことを確認する
27. **(iOS実機・確認済み)** 共有画面で「共有する」を押すと、選択中のテンプレートの画像が生成され、iOSの共有シートが開くことを確認する
28. **(新規・要確認)** 寄り道スポット探索画面でカテゴリチップ(おすすめ/ごはん/カフェ/絶景/温泉/アクティビティ)を切り替えると、地図上のマーカーとスポットカードが同じカテゴリのものだけに絞り込まれることを確認する。「おすすめ」では全カテゴリのスポットが表示されることを確認する
29. **(新規・要確認)** スポットカードを選ぶと対応するマーカーが選択状態(色が変わる)になり、マーカーをタップすると対応するカードへスクロールして選択状態になることを確認する(カテゴリ切り替え後も含む)
29-2. **(新規・要確認)** 地図を手動でズームイン/パンしたあとにマーカーやカードを選択しても、地図が全体表示へ戻らず、ズーム量を保ったまま選択したスポットへ軽くセンタリングされることを確認する
30. **(新規・要確認)** 「ここ寄ってみる」で3件目まで選べ、4件目を選ぼうとすると案内メッセージが表示されて選べないこと、「行くのをやめる」で選択を外せることを確認する。1件も選ばずに「このルートでナビ」でも進めることを確認する
31. **(新規・要確認)** スポットが存在しないカテゴリを選んだ場合、エラー画面にはならず、案内メッセージが表示されたうえで他のカテゴリへ切り替えられることを確認する(モックデータの構成上、通常は発生しない想定ですが念のため確認してください)
32. **(新規・要確認)** 出発地点選択画面・条件入力ウィザードの各画面上部に「1 / 7」〜「7 / 7」の進捗表示が出て、ステップを進むたびに数字とドットが増えることを確認する
33. **(新規・要確認)** 「今日の気分」のチップを4つ目まで選ぼうとすると案内メッセージが表示されて選べないこと、選んだチップをもう一度押すと選択が外れることを確認する。「おまかせ」を選ぶと他の選択が解除され、他の気分を選ぶと「おまかせ」が解除されることを確認する
34. **(新規・要確認)** 「どれくらい走る?」で「自分で入力」を選ぶと日・時間・分の入力欄が表示され、数字キーボードで入力できることを確認する。合計を15分未満(例: 0日0時間10分)にすると警告文が表示され、「次へ」が押せなくなることを確認する。15分以上にすると警告が消え「次へ」が押せることを確認する

## 現在の進捗

ホーム→出発地点選択→ドライブ条件入力→ルート比較→ルート決定確認→ドライブ開始→記録→終了→記録結果確認→日記作成→日記確認→**共有テンプレート選択→共有プレビュー→システム共有**、までを実機で通して操作できる縦断機能を実装しました。ルート提案・地図データはすべてモックです。ドライブ記録は実GPS(expo-location)を優先し、Expo Go等で実GPSが使えない場合は選択中ルートに沿ったデモ走行モードへ自動的にフォールバックします。日記にはタイトル・メモ・日付を入力でき、走行距離・走行時間・選択したルート・経由したスポットは記録結果からそのまま表示します。写真は端末の写真ライブラリ(expo-image-picker)から最大3枚選べ、使えない環境でも日記作成自体は続けられます。日記はPHOTO/DATA/MEMORYの3種類の共有カードに変換でき、記録したGPS座標は正規化した相対座標のグラフィックとしてのみ描画し、開始・終了地点付近は既定で一部間引いて表示します(地図タイル・地図アプリのスクリーンショットは不使用)。共有はOS標準の共有シート(react-native-view-shot + expo-sharing)のみを使い、Instagram専用APIには接続していません。記録・日記・共有カードの元データはアプリ内状態(React Context)に保持し、将来のAsyncStorage等への永続化から再利用できる形にしていますが、端末・クラウドへの永続保存は未実装です。寄り道スポット探索画面には「おすすめ/ごはん/カフェ/絶景/温泉/アクティビティ」のカテゴリチップを追加し、地図マーカーとスポットカードを同じカテゴリで絞り込めるようにしました。ボタン・ラベルの文言も「経由地に追加」→「ここ寄ってみる」のように、ナビ用語から柔らかい言い回しへ変更しています(スポット選択は引き続き完全に任意です)。ドライブ条件入力画面も「今日はどんなドライブにする?」という体験に作り替え、「今日の気分」(景色重視/海沿い/山道/夜ドライブ/のんびり/寄り道多め/短時間/帰宅時間重視、最大3つまで複数選択・任意)をチップで選べるようにしました。「どれくらい走る?」はプリセットのチップに加えて「自分で入力」で時間・分を数字入力でき、「何時ごろ戻る?」も「時刻を指定」で時・分を数字入力して任意の時刻を設定できます(0分・負数・範囲外の値は安全な範囲に自動で収まります)。選んだ気分に応じて、提案される3ルート(景色重視ルート/バランスルート/のんびりルートまたは短時間ルート)の距離・所要時間・タグ・向いている人の説明が変わり、選んだ条件は「景色重視・2時間30分・18:30まで」のような自然な文章でルート比較・ルート決定確認画面の両方で確認できます。ドライブ条件入力は、さらに「今日の気分→どれくらい走る?→最後はどこにする?→経由したい場所はある?→何時ごろ戻る?→AIに追加で伝えたいこと→条件確認」と1ステップずつ進むウィザード形式に作り替え、「今日の気分」に「とにかく走りたい」「おまかせ」を追加(排他選択)、「最後はどこにする?」の「別の場所」を地図で実際に指定できるように、「経由したい場所はある?」でユーザーが優先的に立ち寄りたい場所を地図・保存済み場所・最近使った場所(いずれもexpo-secure-store保存)から追加できるように、帰着日時をISO 8601形式にして日付をまたぐ指定に対応、自由記述の「AIに追加で伝えたいこと」を追加しました。条件確認画面から各項目を個別に編集でき、「今日のルートを見つける」を押すと「あなたに合うドライブを考えています」という短い演出(モック、将来AI API接続に差し替え予定)を挟んでルート提案に進みます。ルート比較画面の「条件を変える」から、入力済みの条件を保持したまま編集を再開できます。

これまでExpo Goでの実機確認で見つかった不具合を修正しています。地図で選んだ場所は確定時のネイティブカメラ中心から取得し、自宅保存中はネイティブの戻る操作による画面離脱も防止します。ルート比較の地図範囲は日付変更線をまたぐ経路も近い地点として計算します。モックルートは帰路を含む全体が時間予算内になるよう生成します。**iOS実機では、自宅変更・保存、地図操作、指定場所選択、ルート切り替え、ルート決定確認画面への遷移、記録結果確認画面からの日記作成(タイトル・メモ・日付入力、写真最大3枚選択、写真なしでの保存、日記確認画面での距離・時間・ルート・スポット・写真の表示)、および日記の共有(テンプレート切り替え、位置情報が文字表示されないこと、画像生成、共有シートの起動)を確認済みです**。

- (1回目・確認済み)ルート比較画面で3つ目のルート(短時間ルート)を選ぶとクラッシュする / 条件入力画面から戻ると現在地取得が終わらない
- (2回目以降・iOS主要操作確認済み)自宅変更・指定場所は確定時のカメラ中心を使用し、座標の有限性と緯度経度範囲を検証。非同期処理のキャンセル、帰着期限を含む時間予算、生成座標の正規化も追加しました

日々の詳細な進捗は [docs/PROGRESS.md](./docs/PROGRESS.md)、ユーザーに見える変更は [CHANGELOG.md](./CHANGELOG.md) に記録しています。

## 既知の制限

- ルート提案はすべてモックデータで、実際の道路形状とは一致しません
- 住所からの場所検索は未実装です(地図上での直接指定のみ対応)
- Web版では地図(react-native-maps)がプレースホルダー表示になり、ルートの視覚的な比較はできません
- ドライブ記録画面は地図を表示せず、現在地を緯度経度のテキストで表示します(`route-plan`での既知の地図クラッシュ問題を踏まえ、当面は地図を持たない構成にしています)
- ドライブ記録はフォアグラウンド(画面を開いている間)のみの記録で、バックグラウンドGPS記録には対応していません
- 日記は1回のドライブにつき1件作成する想定のプロトタイプで、過去の日記を一覧・編集・削除する画面はまだありません(ホーム画面の「記録を見る」は引き続き準備中です)
- 共有カードのPHOTOテンプレートは「日付」のみの表示で、エリア名(逆ジオコーディング)には対応していません
- 共有はInstagram専用APIを使わずOS標準の共有シートのみのため、Instagram Storiesへの直接投稿までは自動化されません(共有シートからInstagramを選ぶ操作は端末側で必要です)
- 「どれくらい走る?」の「自分で入力」は日0〜7・時間0〜23・分0〜59の数字入力で、合計15分未満は次へ進めずブロックされます(ネイティブのTimePicker等は使わず、既存のテキスト入力コンポーネントのみで実装しています)
- 帰着日時はISO 8601形式(例 `2026-09-03T02:00:00+09:00`)で保持し、日付+時刻を明示的に指定するため、日付をまたぐ帰着(翌日・明後日・任意の日付)を正しく扱えます。天気・実交通情報との連携はしていません
- 「経由したい場所」はルート名・おすすめ理由などの表示のみに反映され、実際の地図上の経路(ポリライン)を経由地点に合わせて変形する処理は今回未実装です
- 「保存済み場所」「最近使った場所」は expo-secure-store に保存され、専用の管理(一覧・編集・削除)画面はまだありません。追加は「経由したい場所」ステップで地図から選んだ場所を保存する形のみ対応しています
- 「最後はどこにする?」の「別の場所」は地図からの指定のみ対応で、検索や保存済み場所からの選択は今回未実装です
- 「あなたに合うドライブを考えています」の演出は固定時間のモック待機で、実際のAI APIには接続していません
- ドライブ記録・日記・共有カードのデータはアプリ内状態(React Context)のみに保持し、アプリを終了・再起動すると失われます。端末・クラウドへの永続保存は未実装です
- スポットのカテゴリ(おすすめ/ごはん/カフェ/絶景/温泉/アクティビティ)はすべてモックデータで、Google Places API等の実データとは接続していません
- 「経由地」等のナビ用語を柔らかい言い回しへ変更したのは寄り道スポット探索画面とその直後のルート確認画面までで、ドライブ記録・日記の画面(記録結果確認・日記作成・日記確認)は今回のスコープ外のため従来の表記のままです
- Androidは将来対応予定です。React Native / Expoによる対応可能な構造は維持していますが、実機未検証のため現時点では動作保証しません
- 有料の外部API(Google Routes, Google Places, Supabase, AI API等)とは未連携です
- ネイティブアプリのビルド設定(iOS/Android)はデフォルトのままです
